# دليل إدارة موقع «ما يضيع والو»

## الوصول إلى لوحة التحكم

افتح المسار `/admin` من نفس نطاق الموقع. ستظهر شاشة تسجيل الدخول إذا لم تكن قد دخلت سابقًا. مالك المشروع يحصل على دور **admin** تلقائيًا عند تسجيل الدخول، ولذلك يمكنه إدارة المحتوى. أي مستخدم آخر يحتاج إلى منحه دور المشرف من جدول المستخدمين في واجهة قاعدة البيانات قبل أن يرى أدوات التعديل.

## المنتجات والخدمات

من قسم **إدارة المنتجات** يمكن إنشاء محصول جديد أو تحريره أو إخفاؤه أو حذفه. الحقول التي تعدّل من الشاشة هي اسم المنتج، التصنيف، المزرعة، المنطقة، السعر، عبارة التوفر، الصورة، وحالة الظهور. يظهر المنتج النشط فورًا في واجهة الزائر، بينما يختفي المنتج المخفي من السوق العام بدون فقدانه من لوحة التحكم.

من قسم **الخدمات** يمكن إدارة بطاقات النقل والتوفير وإعادة التوزيع أو إنشاء خدمات جديدة. تستطيع ترتيب الخدمات بالأرقام، اختيار أيقونة مناسبة، ثم إخفاء أو حذف أي خدمة عند الحاجة.

## المظهر ومحتوى الصفحة

قسم **المظهر والمحتوى** يتضمن نص الإعلان العلوي، عنوان الواجهة، الوصف، عنوان المنتجات، عناوين الخدمات والأثر والمساعد، بريد التواصل، اللونين الأساسي والمميز، وصور الواجهة والخريطة. استخدم زر **حفظ التغييرات** بعد أي تعديل؛ لا يلزم تعديل الكود أو إعادة بناء الواجهة يدويًا.

> الموقع يبدأ بدون منتجات أو خدمات حقيقية عمدًا. أضف بياناتك الفعلية من لوحة التحكم؛ لا توجد تقييمات أو آراء مستخدمين تجريبية ضمن المشروع.

## التحقق المحلي

يستخدم المشروع الأوامر التالية للتحقق قبل الدفع إلى GitHub:

| الأمر | الغرض |
| --- | --- |
| `pnpm check` | فحص TypeScript |
| `pnpm test` | تشغيل اختبارات التحقق من البيانات وصلاحيات الإدارة |
| `pnpm build` | بناء نسخة الإنتاج |

## GitHub والاستضافة

يمكن رفع الكود كاملًا إلى GitHub دون تنزيل يدوي. لكن الموقع الآن يعتمد على خادم، قاعدة بيانات، تسجيل دخول، وتخزين صور؛ لذلك **GitHub Pages وحده لا يكفي لتشغيل لوحة الإدارة**. احتفظ بـ GitHub كمستودع للكود والإصدارات، واستخدم الاستضافة المدمجة في المشروع أو بيئة خادم متوافقة لتشغيل النسخة الحية.
